## 1.1 Extraction pipeline (build-time, deterministic, idempotent)

New file: `08_SELF_IMPROVEMENT/corpus_extractor.py` (English, stdlib only).

1. **Freeze first.** Copy the 6 snapshots + `messages.jsonl` + `history-catalog.json` +
   `manifest.json` + `user-message-locators.jsonl` into `09_LOGS/corpus_freeze/`, write a
   `SHA256SUMS.txt`. Never read the live files again for extraction. Reason: compaction can
   rotate/overwrite generations; the freeze converts a volatile source into a stable one.
   *(Prerequisite for everything else in Plan 1.)*
2. **Parse** each JSONL line as `{message_id, turn_id, message:{role, content|summary, …}}`.
3. **Extract text**: for user/assistant, concatenate `content[].text`; strip
   `` blocks (they are harness scaffolding, not Popy's words)
   but **retain them separately** in a `scaffolding` field so nothing is lost.
4. **Dedupe by `message_id`**, keeping the **longest** occurrence. A message id present in gen 0 and
   gen 4 is the same message; the later copy may carry more parts.
5. **Order chronologically**: primary key = generation index, secondary = line index within
   generation. `turn_id` is preserved as a grouping key (turns end in `:compaction` when
   compaction occurred). Do **not** re-sort by wall clock — generation order is the true order.
6. **Assign `seq`** (1..N) and `turn_index`; emit `corpus_full.jsonl` +
   `CHANGELOG_EXTRACTION.md` with a per-message `source: {generation, file, line, byte_offset}`.
7. **Integrity assertions** (fail loudly, never warn-and-continue):
   - first `seq==1` text equals the verified message-zero string;
   - every message in every generation appears in the output or is listed as an explicit exclusion;
   - user-message count across generations ≥ the max per-generation count;
   - output byte length ≥ 95 % of the sum of generation bytes (any larger shortfall means content
     loss — investigate before proceeding).
8. **Idempotency**: re-running on the frozen input produces a byte-identical output (hash compared).

## 2.2 Mandatory code fix — real STOPPED state

Change `bimodal_workflow.py` so the law is a mechanism, not a comment:

1. `_stop(reason)` sets `self.mode = WorkflowMode.STOPPED` **before** transitioning, and preserves
   `self.stop_reason` and a new `stopped_at` timestamp.
2. `halt_to_mode_a()` must **not** clear `stop_reason`; it takes an explicit
   `clear_stop: bool = True` and callers pass `False` when halting *because of* a stop.
3. `enter_mode_a()` records `previous_mode` and `halt_reason` in history, and — when entered from
   STOPPED — only then clears `stop_reason` and returns to MODE_A. This preserves the doctrine's
   two distinct behaviours: *interruption → MODE_A* and *STOP → report and wait*, which today are
   indistinguishable.
4. `persist()` is called **after** every state mutation, including the `stop_reason = None` write.
5. `is_stopped()` returns `self.mode is WorkflowMode.STOPPED or self.stop_reason is not None`
   (unchanged) — and now the underlying state actually holds.
6. New method `acknowledge_stop(user_input: str) -> None`: the **only** legal exit from STOPPED,
   and it logs the user input that authorized resuming. This encodes "STOP = ask and wait" as an
   enforced transition, not advice.
7. New tests: after a 5-failure STOP, assert `mode == STOPPED`, `stop_reason` non-empty, survives
   `persist()`/`load()` round-trip, and that `execute_step` refuses while stopped; assert
   `acknowledge_stop` is the only path out; assert a *fresh* `BimodalWorkflow()` loading the state
   file still reports STOPPED (the persistence half the current tests miss).
